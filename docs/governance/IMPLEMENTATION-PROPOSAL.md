## 업무 계층과 기록 시점

`calc/audit/context.py`, `schema.py`, `writer.py`, `reader.py`, `retention.py` 분리 제안. 미들웨어는 서버 UUID와 검증된 네트워크 문맥만 준비한다. POST 폼 검증·실제 소유권 확인·변경 비교는 업무 서비스에서 처리한다. GET에서 발생하는 Profile/Portfolio/한국사 자동 생성은 가능한 한 명시적 초기화/POST 서비스로 옮긴다. 유지해야 하는 생성에는 실제 created 결과를 기록한다.

가입의 User/Profile, 점수 저장/삭제와 ItemStatus/ScoreChange 등 하나의 업무 변경을 `transaction.atomic()`으로 묶고 `transaction.on_commit()`에 **값으로 복사한** 이벤트를 전달한다. 롤백 시 성공 이벤트가 없어야 한다. 기존 데이터와 동일하면 noop, 생성과 갱신을 구분한다. 삭제 전에 PK·최소 상태를 확보한다. 비밀번호 변경 이벤트에는 비밀번호 값을 전달하지 않는다.

DB 커밋과 파일 append는 원자적이지 않다. 커밋 뒤 프로세스 종료·디스크 오류로 이벤트가 빠질 수 있다. 이 한계와 실패 건수를 상태에 표시한다. 로그 실패 때문에 이미 저장한 업무를 실패했다고 응답하면 중복 제출 위험이 있으므로 업무 결과는 유지한다. 무누락이 요구되면 별도 합의로 내구성 보강을 설계하고 DB 행동 원본이나 외부 플랫폼으로 조용히 바꾸지 않는다.

기본 Django admin에는 ModelAdmin 저장/삭제/일괄 삭제 및 User/Group 권한 변경을 연결한다. 기존 `LogEntry.object_repr`에는 모델 `__str__`가 사용될 수 있고 Suggestion 문자열에 본문, Profile 문자열에 계정·점수가 포함되므로 운영 기록 최소화 및 기존 이력의 원문 잔존 범위를 점검한다. 과거 기록은 조사 없이 변경·삭제하지 않는다.

## JSONL schema v1 계약

운영 `C:\caddy\logs\AuditLog\promotion-calculator\`, 개발 `<project_root>\.runtime\user-actions\`, 파일 `user-actions-YYYY-MM-DD.jsonl`. UTF-8 한 줄 한 객체, KST 날짜 경계 제안, timestamp는 UTC. 개발 디렉터리는 향후 gitignore 대상이며 정적/media URL로 제공하지 않는다.

| 필드 | 타입·검증 제안 / 의미 |
|---|---|
| schema_version | 정수 1 |
| event_id | 서버 생성 UUID 문자열, 이벤트마다 새 값 |
| timestamp | UTC ISO 8601, 타임존 필수, 화면 KST |
| request_id | 서버 생성 UUID 문자열, 같은 요청에서 공유 |
| user_id | 현재 Django 정수 PK 또는 null; 로그인 실패·재설정 요청은 null |
| action | 등록된 domain.action, 최대 80자, 적용표 이벤트 목록 |
| object_type | 등록된 모델/도메인 이름 최대 64자 또는 null |
| object_id | 현재 정수 PK 또는 null; 대상 삭제 후에도 값 보존. 신규 문자열 ID는 별도 타입 매핑 문서화 |
| outcome | success / failure / denied / noop 열거형 |
| reason_code | 등록 코드 최대 64자 또는 빈 문자열; 예: invalid_input, forbidden, not_found, unchanged |
| client_ip | 검증된 IPv4/IPv6 문자열 또는 null |
| ip_source | 배포에서 검증한 출처 코드 또는 unknown. direct/proxy 코드의 의미를 배포 문서에서 고정 |
| cf_ray | 신뢰 경유 확인 시 길이·문자 검증한 보조값 또는 null; 유일성 보장 안 함 |
| route | resolver_match.view_name 최대 150자 또는 빈 값. raw URL·query·reset token 금지 |
| metadata | 작은 객체, 허용 키만. 예: item_code, changed_fields(필드명만), previous_status/new_status, count. 자유 텍스트·점수 값·기관명 금지 |

길이 제한은 공통 의미를 바꾸지 않는 구현 제안이다. metadata 최대 2KiB, 한 이벤트 최대 8KiB를 시작 후보로 검증하며 초과·알 수 없는 키는 오류로 관측하고 무제한 저장하지 않는다. 날짜/UUID/IP/enum은 writer 입력과 reader 모두 검증한다. 줄바꿈은 JSON 인코더로 이스케이프해 한 줄 계약을 유지한다.

금지: 비밀번호·쿠키·세션/CSRF/인증/재설정 토큰·POST 본문·입력 아이디/이메일·기관/인증번호·점수·메모·문의/첨부 원문·검색어·User-Agent/Referer 원문·전체 예외 문자열. 진단 오류에도 이 값들이 유출되지 않게 한다.

writer는 Windows에서 프로세스 간 잠금과 완전한 한 줄 append, 닫기/flush 정책을 검증한다. 경계 정리와 append는 같은 잠금 규약을 사용한다. 임시파일 원자 치환 실패는 원본을 보존하고 오류로 남긴다. 잠금 시간 초과·부분 줄·스키마 손상·디스크 부족을 별도 상태로 보고한다. 재시작 후 ‘최근 성공’을 디렉터리 존재로 추정하지 않는다.

## 운영 기록과 개인정보 접근기록

운영 기록은 최소 actor_id 스냅샷·시각·action·대상 ID·이전/새 상태·request_id를 가진 별도 DB 모델을 제안한다. 필요하면 기존 대상 FK는 SET_NULL로 두고 식별자 스냅샷을 보존한다. 계정 탈퇴가 운영 기록 전체를 CASCADE하지 않도록 설계하되 보존 기간을 먼저 정한다. 업무 원문은 감사 모델에 복제하지 않는다. 기본 admin 이력과 연결 키를 두어 이중 표시를 방지한다.

개인정보 접근기록은 별도 목적·기간을 갖는다. 적용 범위 확인 후 담당자 ID·시각·접속지·조회 대상 정보주체 ID·수행 업무·request_id, 다운로드 시 해당 사실과 필요한 사유를 최소한으로 기록하는 설계가 필요하다. 목록도 대상 범위를 설명할 수 있어야 하며 단순 ‘페이지 열림’으로 대체하지 않는다. 실제 열람 원문은 복제하지 않는다. 고시의 정확한 필수 필드·점검 주기·보존 기간·시행 경과는 법률 검토가 남아 있다.

대시보드의 최근 username/문의 제목도 개인정보 조회에 해당할 수 있으므로 ‘개인정보와 개인 점수 원문을 제외’라는 설명을 그대로 유지하지 않는다. 기본 통계를 개인정보 없는 결과로 제한하거나 별도 개인정보 권한/접근 기록을 붙인다. 파일 조회도 `is_staff`만 확인하지 않고 문의 열람 및 첨부 열람 권한을 요구한다.

## 관리자 목록·상세 화면 명세

기존 브랜드/CSS를 사용하면서 관리자 사이드바를 분리한다. 메뉴 순서는 대시보드 → 신고(비해당 숨김) → 작성물(공개 관리 비해당 숨김) → 회원 → 평정 자료 → 공지 → 문의 → 역할 → 운영 기록 → 이용자 행동 로그. 개인페이지 옆 관리자 진입과 사이트 복귀를 제공한다.

`/manage/user-actions/` 목록:

1. 제목 **이용자 행동 로그**, 정확한 현재 조회 범위를 KST로 설명.
2. 기록 상태: 활성/비활성, 최근 기록 성공·실패 시각, 확인 가능한 데이터 범위, 최근 파기 결과·보존기간. ‘데이터 없음’, ‘미수집 기간’, ‘기록 실패’, ‘손상된 줄’, ‘조회 상한’, ‘커서 만료’를 구분.
3. 기간 → 회원 ID → 행동 → 대상 종류 → 대상 ID → 결과 → 요청 ID → 조회·초기화. datetime 입력으로 요청 시점 기준 정확한 최근 24시간을 기본값으로 설정. `end-start <= 7일`, 페이지 크기 50. 과거 보존분도 임의의 7일 구간 조회 가능.
4. 권한 있는 실제 IP 검색을 별도 POST 폼으로 제공. 실제 IP는 URL·히스토리·리퍼러에 싣지 않는다. CSRF 보호, 정규화, 기간·타 필터와 함께 서버 측 검색 문맥에 저장.
5. 열 순서: **시각(KST) / 회원 / 행동 / 대상 / 결과 / IP / 요청 ID**. 회원은 내부 ID가 기본이며 username 이메일을 기본 출력하지 않음. IP는 기본 마스킹; cf_ray도 network 권한이 있어야 응답에 포함.
6. 검색 조건을 유지하는 이전/다음 페이지. 순서는 timestamp 및 event_id 등 안정적인 보조 키로 고정하고 커서는 파일 위치/상태와 연결.

`/manage/user-actions/<event_id>/` 상세: 대상 → 관련 정보 → 가능한 조치(request_id 복사·권한 있는 살아 있는 대상 링크) → 동일 요청 관련 이력 순서. JSON/metadata는 escape된 텍스트, 삭제 대상은 삭제 표시만. 편집·수동 삭제·대량 내보내기 없음. 목록에서 선택한 기간 문맥을 사용하며 최근 고정 N일만 검색해서 과거 상세가 깨지지 않게 한다.

응답은 `Cache-Control: no-store`. 실제 IP/cf_ray는 HTML 숨김이 아니라 서버 직렬화 단계에서 제외/마스킹한다. 서명된 커서는 관리자·검색 조건·만료와 결합, IP 원문은 포함하지 않는다. 서버 검색 문맥은 짧은 만료와 사용자 결합을 적용하고 매 페이지 권한 재검사한다. 파일 변경/삭제 시 오류를 구분하고 재조회 안내. 스캔 바이트·행·파일 수 제한과 실행 시간 상한을 두고 부분 결과를 완전한 결과처럼 표시하지 않는다. 수치 상한은 운영 파일 규모 측정 후 확정한다.

모바일은 접는 메뉴와 열 줄바꿈/안전한 가로 스크롤, 키보드 초점·모든 필터 라벨·aria-expanded·빈/실패 상태 텍스트를 검증한다. 상태는 색과 텍스트를 함께 사용한다. 현재 app.js의 메뉴 토글은 aria-expanded 업데이트가 없어 보완 후보다.

공지 상세는 대상 → 게시 상태/관련 정보 → 초안 편집·게시·종료(각 권한) → 운영 이력. 현재 boolean만으로 초안과 종료를 구별할 수 없으므로 상태값 도입 및 기존 공개 여부에서의 안전한 이관안을 마련한다. 문의는 접수 → 확인 중 → 완료, 완료 → 확인 중 재개를 명시하고 상태 변경·메모 수정·담당자를 이력에 남긴다. 반복 완료 POST가 완료 시각을 새로 쓰는 현행 동작도 noop 처리 대상으로 검토한다.

## 보관·삭제와 문서 버전

달력 월 계산은 KST 기준에서 3개월 전 같은 날짜/시각, 없는 날짜는 월말로 보정한다. 예: 2026-05-31에서 3개월 전은 2026-02-28, 2024-05-31이면 2024-02-29. cutoff 미만만 만료, 동일 시각은 유지한다. 파일 경계일을 통째로 지워 아직 만료되지 않은 행이 사라지지 않게 한다. 정리 dry-run에 대상 파일·만료 건수·예상 보존·오류만 출력한다. 타 프로젝트 경로·심볼릭 링크/재분석 지점 우회·예상 밖 파일명은 거부한다.

첨부 파기는 DB 커밋 뒤 처리하고 실패 재시도·경보를 마련한다. FileField 삭제·교체·탈퇴·admin 일괄삭제 모두 포함하고 다른 레코드가 참조 중인 파일을 지우지 않는다. 실서비스 파일로 테스트하지 않는다. 브라우저 초기화는 계정탈퇴와 독립이므로 탈퇴 화면에 남은 localStorage 삭제 경로를 제공한다.

약관/방침은 날짜별 새 파일 + 현재 버전 참조 + 이전 버전 아카이브, 가입 동의는 문서 버전·시각·회원과 결합하는 append-only 기록 제안. 필수 약관 동의와 선택 동의는 구분한다. 방침 열람 확인을 개인정보 수집 동의로 대체하지 않는다. 기존 회원의 동의 시각/버전은 만들어 넣지 말고 ‘과거 증빙 없음’으로 이관한다. 실제 게시·시행 날짜·개정 비교·공지/추가 동의 여부가 확정될 때만 참조를 전환한다.

## 검증과 출처

실제 검증 상태는 적용표 TEST-01~12를 따른다. 현재 의존성 누락으로 기존 테스트가 시작 실패했으며 새 구현이나 새 테스트는 작성하지 않았다. 구현 단계에서는 위 경로별 분기와 파일 동시성·커서·실패 상태를 격리된 DB/임시 디렉터리·가짜 계정으로 검증한다.

- 트랜잭션 설계 참고: [Django 5.2 transactions](https://docs.djangoproject.com/en/5.2/topics/db/transactions/). 구현 시 배포 버전에서 API 확인 필요.
- 서버 확인 대상: [Caddy log](https://caddyserver.com/docs/caddyfile/directives/log), [Caddy log_append](https://caddyserver.com/docs/caddyfile/directives/log_append), [Cloudflare headers](https://developers.cloudflare.com/fundamentals/reference/http-headers/). 실제 운영 설정은 확인하지 않았으며 복사 배포하지 않는다.
