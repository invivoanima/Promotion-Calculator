# 서버 확인·적용 안내 — 제안만

2026-09-09. 실제 서버 설정·로그·서비스 계정은 미확인이다. 이번에는 운영 경로 생성, 설정 덮어쓰기, 예약 작업 등록, 로그 삭제를 수행하지 않았다. 아래는 후속 구현이 검증된 후 서버 담당자가 실행할 작업이며 실행 스크립트가 아니다.

| 단계 | 확인·제안 | 검증 증빙 |
|---|---|---|
| 실제 배포 확인 | 도메인·원본 IP·Cloudflare 기능/계약, Caddy 실제 설정 파일 위치, Waitress 실행 명령/서비스 계정/작업 디렉터리·포트 확인 | 비밀값을 제거한 설정 요약, 서비스 이름·포트·경로. 저장소 예시로 대체하지 않음 |
| 환경·의존성 | production 명시, DEBUG=False, 영구 DB/MEDIA_ROOT, requirements와 런타임 버전 일치, SMTP backend 설정 확인 | 로컬은 dotenv 누락으로 테스트 시작 실패. 운영도 정상이라고 추정하지 않음. settings의 `.env` 로드와 README 차이 정정 필요 |
| 기존 접속·오류 로그 | Caddy/Waitress 로그 유지, 실제 경로·필드·회전·보존·오류 출력 대상 확인 | 사용자 값 없는 키 목록·집계. 샘플 하나를 무누락 증명으로 쓰지 않음 |
| 프록시 신뢰 | 원본 우회 차단 또는 신뢰된 peer 검증, forwarded 헤더 교체/정규화, IPv4/IPv6 검증 | 위조 CF-Connecting-IP/XFF/X-Request-ID로 실제 IP/요청 ID를 바꿀 수 없는지 시험. 미확인이면 null/unknown |
| 요청 연결 | 앱 생성 X-Request-ID를 응답하고 Caddy 응답 로그 필드로 수집 | 앱 이벤트와 Caddy 동일 UUID. CF-Ray는 보조값, 앱에 오지 않은 요청의 user_id 추정 금지 |
| 접속 로그 최소화 | Cookie/Set-Cookie/Authorization 보호, query·reset token 경로·검색어·불필요 헤더 점검 | 비밀값이 접속·오류 출력에 없는지 테스트. 회원 ID 응답 헤더 추가 금지 |
| 감사 경로·권한 | `C:\caddy\logs\AuditLog\promotion-calculator\`만. 서비스 계정 쓰기, 지정 조회 계정 읽기, 파기 담당 최소 삭제 권한. 일반 사용자·웹 정적 제공 차단 | NTFS ACL 상속·타 프로젝트 접근·재분석 지점 우회 검사; 무권한 계정 접근 실패 증거 |
| 회전·용량·시간 | KST 일별 파일/UTC 이벤트, 프로세스 간 잠금, 디스크 여유·쓰기 실패·시간 동기화 감시 | 일 경계·여러 writer·재시작·디스크 부족 시험. 용량 초과로 오래된 파일 임의 삭제 금지 |
| 보관·파기 | 유형별 근거/기간 확정 후 dry-run 가능한 정리 명령과 일일 실행 후보 | 월말/윤년/경계 파일·무트래픽·최대 지연·실패 경보. 기존 90일 DB 명령을 JSONL 달력 3개월 명령으로 사용하지 않음 |
| 백업·복사본 | DB/첨부/각 로그의 백업 위치·보유 주기·외부 업체·만료 확인 | 원본 삭제 후 복사본 기간 추적, 복원 시 삭제 대상 재정리. 법적 보존 대상은 별도 통제 |
| 미디어 보호 | `media/suggestion/` 직접 URL·Caddy 파일서빙 우회 차단 | 본인/권한 담당자만 Django 파일 route로 열람, 탈퇴·교체·일괄 삭제 파기 시험 |
| 개인정보 조회 | 대시보드·admin·문의/파일·실IP 조회기록 범위와 기간 별도 확정 | 법적 적용 검토 및 누락 없는 조회 경로 목록. GET 접속 로그로 대체 불가 |

앱의 신규 JSONL 기록이 기존 Caddy/Waitress를 대체하지 않는다. 기존 DB AccessLog를 중단·대체할 때는 대시보드 집계 의존성과 기존 행의 적법 보존/파기 계획을 먼저 정한다. 앱과 서버 변경은 배포 단위·담당·적용 시각·검증 결과를 각각 남긴다.

수사기관 등 제공 요청은 요청기관/문서 진위 → 법적 근거/자료 종류/기간/대상 확인 → 필요한 기존 기록만 조회 → 정당한 별도 보존 시 사유/범위/종료 기준 기록 → 원본 보존 및 복사본 해시·추출 조건·담당자·시각 기록 → 허용 범위 제공 및 종료 후 파기 순서로 처리한다. IP/계정은 실제 사람의 신원 증명이 아니며 삭제된 원문을 행동로그로 복원할 수 없다. 자동 제공 API는 제안하지 않는다.

운영 완료 조건: 확인된 실제 설정, 최소 ACL, request_id/IP 신뢰 시험, 로그 실패 경보, 정리 스케줄과 무트래픽 시험, 백업 만료, 역할별 화면 검증, 문서/동의 시행일 일치의 증빙이 모두 있어야 한다. 현재 상태는 전부 미적용이다.
