# 지역·연도별 전체 점수 계산 구조

적용일: 2026-10-19

## 원칙

개인 정보에서 선택한 지역은 경력·근무성적·연수·공통가산점·선택가산점을 포함하는 **전체 규칙 모듈**을 선택한다. 공통가산점이라는 이름은 전국 동일 계산식이라는 의미로 사용하지 않는다. 참고 계산을 선택한 경우에는 참고 지역의 모듈을 사용하며 대표 지역은 변경하지 않는다. 대시보드는 대표 지역 기준이다.

기준이 등록되지 않은 지역·연도에는 다른 지역 규칙을 대입하지 않는다. 준비 중 화면을 보여 주며 모든 점수 영역의 저장·계산 요청을 차단한다. 현재 17개 지역의 2026년 모듈을 등록했다. 전남 외 16개 지역은 선택가산점을 제외한 9개 항목의 법령 기반 기본 계산이며 교육청 원문 검증은 미완료다.

## 파일과 책임

```text
calc/
  regions.py                          지역 이름과 등록 상태
  catalog.py                          지역을 명시해야 하는 항목 조회 API
  services.py                         지역 선택, 기록 조회, 원입력 재계산, 모듈 호출
  scoring/
    registry.py                       (지역, 적용 연도) → 규칙 모듈
    utils.py                          날짜·Decimal 연산; 배점·상한 없음
    regions/
      seoul/, busan/, .../             나머지 16개 지역도 동일한 독립 폴더 구조
      jeonnam/
        v2026/
          __init__.py                 항목 분배, 지역 최종 합산, 화면 보완 정보
          catalog.py                  모든 영역의 입력 정의·배점 안내·상한
          precision.py                이 지역·연도에 적용하는 점수 정밀도
          career.py                   경력평정
          work.py                     근무성적평정
          training.py                 자격·직무연수, 연구실적과 입력 검증
          common_bonus.py             전남 공통가산점
          regional_bonus.py           전남 선택가산점
  templates/calc/
    new/score_item.html                지역 고유 배점표가 없는 기본 입력 틀
    new/rules_pending.html             지역 전체 규칙 미등록 상태
    regions/jeonnam/v2026/score_item.html
                                      전남의 원문 표·세부 안내가 포함된 입력 화면
```

기존 공용 `CATEGORIES`, `ITEM_BY_CODE` 등 전남 기본 카탈로그는 제거했다. `get_ruleset(region_code)` 또는 `get_item(..., region_code=...)`로 선택한다. UI 입력 정의와 입력 검증도 같은 모듈에서 가져온다. 새 지역의 화면에 전남 배점표가 자동으로 붙지 않는다.

`calc/services.py`에는 단가·점수 상한·연수 인정기간을 두지 않는다. 원입력을 지역 모듈에 전달하고 결과를 모은다. 카테고리 상한·정밀도·항목 간 조정은 각 모듈의 `finalize_summary()` 책임이다.

## 호출과 저장

1. 회원은 대표 지역 또는 명시적으로 열어 본 참고 지역으로 모듈을 선택한다. 비회원은 선택한 지역으로 모듈을 선택한다.
2. 모듈의 입력 정의로 폼을 구성하고 `validate_input()`으로 해당 지역의 입력 조건을 검증한다.
3. 저장 시 `calculate_record_score()`를 선택한 모듈로 호출한다.
4. 합산 시에는 저장된 `calculated_score`를 그대로 신뢰하지 않고, 원입력을 같은 지역 모듈로 다시 계산한다. DB 기록을 변경하지 않도록 사본에서 처리한다.
5. 지역 모듈이 항목 점수와 최종 합계를 산정한다. 결과에는 `region_code`와 `rule_year`가 포함된다.

이번 변경은 DB 분할이 아니다. 기존 `national` 범위의 원입력 기록과 지역별 `RegionPortfolio` 기록을 보존한다. 기존 전국 공통 원입력도 최종 점수는 선택 지역의 규칙으로 다시 계산한다. 다른 지역의 포트폴리오 기록을 섞어 계산하려 하면 오류로 거부한다. DB 스키마 변경이나 기존 기록 일괄 재저장은 없다.

새 16개 모듈의 자격연수는 기존 전남의 1급 정교사 자격연수와 평정 대상이 다른 교감 자격연수이므로 지역별 포트폴리오에 저장한다. 기존 전남 자격연수 원입력을 교감 자격연수로 바꾸어 계산하지 않는다. 경력·근무성적·직무연수·연구실적의 기존 전국 범위 원입력은 계속 공유한다.

비회원 저장 키는 `promotionCalculator.guestRecords.v1.<지역>.<연도>`다. 기존 단일 키는 전남 화면에서만 읽을 수 있도록 호환하고, 새로 저장하면 전남 전용 키에 쓴다. 다른 지역에는 이전 단일 키를 가져오지 않는다. 기존 단일 키에는 지역 정보가 없으므로 이전 입력의 출처를 판별하는 기능은 없다.

## 지역 모듈 인터페이스

등록 모듈은 다음 정보를 제공한다.

- `REGION_CODE`, `RULE_YEAR`, `RULE_DATE`, `ROSTER_DATE`
- `CATEGORIES`, `CATEGORY_BY_CODE`, `ITEMS`, `ITEM_BY_CODE`
- `calculate_record_score(record)`
- `calculate_item_score_from_records(item_code, records)`
- `validate_input(item, cleaned_data)` → 필드명·오류 메시지 목록
- `finalize_summary(summary, record_map)` → 카테고리 점수·총점을 포함한 결과
- `mark_selected_records(records, item_code)` → 화면에 표시할 반영 정보
- `item_context(item_code, score_for_item)` → 자격연수 보완 가능 범위 등 지역별 보조 정보
- 선택: `SCORE_ITEM_TEMPLATE`, `MANUAL_STATIC_PATH`, `RESOURCE_NOTES`
- `REGIONAL_BONUS_AVAILABLE`: 선택가산점의 제공 여부. 지역 모듈 등록 여부와 별개다.
- `VERIFICATION_STATUS`, `RULE_NOTICE`, `SOURCE_LINKS`: 구현 상태와 원문 검증 상태 및 근거
- `VALIDATE_GUEST_STORAGE`: 비회원 저장값을 현재 지역 폼으로 재검증 (새 16개 모듈에서 활성화)

등록된 지역의 계산식을 바꿀 때는 그 지역의 `v2026/` 폴더만 고친다. `policy.py`는 학점 상한·인정기간·출처, `catalog.py`는 입력 정의·안내, 각 카테고리 파일은 계산·선택·집계, `__init__.py`는 검증·최종 합산을 담당한다. 단가·상한을 바꾸면 카탈로그의 표시값도 함께 일치시켜야 한다. 새 16개 지역의 학점 한도는 계산과 화면이 동일한 로컬 `policy.py` 값을 사용한다.

새 지역을 추가할 때에는 자체 폴더를 생성하고 `registry.py`의 지역 코드·모듈과 `calc/regions.py`의 이름을 등록한다. 새로운 연도는 별도 `v연도/`를 만들고 등록한다. 등록 시 모듈이 선언한 지역·연도가 키와 다르면 로드를 거부한다. 검증되지 않은 지역을 전남 모듈의 별칭으로 등록하지 않는다. 공유 유틸리티에는 배점·상한을 넣지 않는다.

기존 입력 필드로 표현할 수 있는 규칙 변경은 공용 서비스나 화면을 바꾸지 않는다. 새 필드 종류나 다른 입력 흐름이 필요하면 해당 지역의 폼·템플릿 확장이 추가로 필요할 수 있다.

## 16개 지역 기본 계산

각 지역은 카탈로그·검증·정밀도·경력·근무성적·연수·공통가산점 파일을 독립적으로 갖는다. 다른 지역 폴더를 import하거나 전남 함수를 호출하지 않는다. 선택가산점은 빈 목록과 상한 0으로 두어 입력 및 총점에서 제외한다. 해당 지역 폴더에 `regional_bonus.py` 자리도 마련했다.

기본 계산은 경력 만기 만점, 근무성적 최종 가중합 최대 조합, 직무연수 성적용 1개+다른 이수용 최대 2개, 연구대회 학년도별 최고 1개와 학위 최고 1개, 학점 연간·총 상한을 처리한다. 새 모듈은 교감 승진 명부의 자격연수 계수 0.05를 사용한다. 전남의 기존 대상자 선발 계산은 이번 확장으로 바꾸지 않았다.

교육청별 원문 검증이 끝나지 않은 지역의 숫자를 확정 규정으로 제시하지 않는다. 모든 계산 페이지에 기본 계산 안내를 표시하고, 자료 화면에 법령 출처와 미확인 범위를 표시한다. 자세한 범위와 한도는 `docs/reviews/2026-regional-baseline-status.md`에 기록한다.

## 검증과 후속 작업

- 서로 다른 테스트용 지역의 **공통가산점** 단가·카테고리 상한·입력 라벨·검증 조건을 주입해 회원/비회원이 해당 지역 규칙을 호출하는지 확인한다. 이 테스트 모듈은 실제 서울 규정이 아니며 테스트 밖에서는 등록되지 않는다.
- 미등록 지역·미등록 연도·지역 없는 계산에 전남 규칙이 적용되지 않는지 확인한다.
- 대표 지역과 참고 지역의 독립, 비회원 키 구분과 기존 키 호환, 포트폴리오 혼합 거부를 확인한다.
- 기존 PDF 비교 38개 사례의 출력은 분리 전후 동일하다. 이는 **구조 분리 과정에서 계산이 바뀌지 않았음**을 확인한 것이며, 원문 미반영 조건이 해결되었다는 의미가 아니다.
- 2026-10-19 검증: 전체 Django 테스트 59개 통과. 분리 전 계산기와 기록 284개 사례 및 19개 항목 합산 결과 일치. `manage.py check`, 마이그레이션 변경 검사, JavaScript 구문 검사 통과.
- 같은 날 16개 지역 확장 후 전체 Django 테스트 73개 통과. 최종 근무성적 반올림 변경은 지역 계산 테스트 11개로 추가 검증하여 통과. 입력 구현과 교육청 원문 검증의 차이는 지역별 적용 현황 문서에 기록했다.

`docs/reviews/2026-manual-calculation-audit.md`의 직무연수 배분, 연구학교 합산 상한, 제6호 목 분류·상한·인정기간 등은 해당 지역 모듈에서 후속 수정해야 한다. 제6호 하위 입력 메뉴와 기존 `regular` 기록 재분류도 이번 구조 분리와 별개의 작업이다.
